## 约束全文（用户原始文本，原样入库）

# 软件工程强制约束（最高优先级）

本约束适用于：任务执行、代码变更、设计文档、后续计划、测试、报告和任何交付物。
与前述 prompt / 后续计划冲突时，以本约束为准。若无法同时满足，暂停并说明冲突，不得自行降低标准。
“严格按软件工程要求”指：可追溯、可验证、可回滚、有测试、有文档、有评审记录；不是过度设计，禁止无必要抽象和大重构。

## 1. 总则
1. 需求可追溯：每个任务必须对应任务号、PRD 条目或明确需求描述；无来源的改动不做。
2. 小步原子变更：一个任务一个分支/一个 PR/一个 commit 集；禁止跨任务混合改动。
3. 先分析后编码：任务开始前必须输出影响分析、设计简述、测试计划、迁移/回滚方案、风险。
4. 没有验证证据不得标记完成：必须提供测试命令、结果摘要、构建/lint/typecheck 结果。
5. 不得伪造：不得伪造测试通过、真机验证、合规审核、KPI 数据；无法执行标 BLOCKED。
6. 不得擅自改需求：代码与 PRD 冲突时暂停并记录，不得自行改需求或改验收标准。
7. 不得提交密钥/凭据/真实患者数据；测试数据必须合成或脱敏。
8. 用户可见变更优先用 feature flag 或可回滚配置；生产配置不得擅自修改。
9. 禁止无关格式化、全文件重写、大规模重构；必要重构必须单独任务并说明理由。
10. 所有文档必须区分：已实现 / 设计目标 / 未实现，不得把目标写成已实现。

## 2. 任务生命周期（每个任务必须遵守）
### 开始前
输出：
- 任务号与需求来源
- 影响范围：模块、文件、API、数据模型、客户端、配置
- 设计简述与备选方案（如有）
- 测试计划：单元/集成/E2E/回归/手工验证
- 数据迁移与回滚方案（如涉及）
- 安全/隐私/合规影响
- 风险与需确认项
- 预计修改文件清单
未输出以上内容，不得开始编码。

### 执行中
- 遵循仓库现有代码风格、目录结构、命名、lint/format 配置。
- 只改必要文件；禁止顺手重构无关代码。
- 新逻辑必须有对应测试；修改逻辑必须更新或补充回归测试。
- API/数据模型变更必须考虑向后兼容；破坏性变更必须单独任务并给迁移方案。
- 数据库迁移必须可回滚或提供补偿脚本；数据修复脚本必须幂等。
- 错误处理、日志、监控按现有模式补齐；日志不得含敏感医疗信息。
- 依赖升级必须有理由、锁文件更新、安全与兼容性说明。

### 完成后
必须输出：
- 变更文件列表与 diff 统计
- 实际行为变化
- 测试命令与结果摘要（失败就是失败，不得含糊）
- lint/typecheck/build 结果
- 安全/隐私检查清单结果
- 文档/变更日志更新情况
- 回滚方式
- 未完成/Blocked 项与原因
- 下一步建议

## 3. 质量门禁
1. 编译/构建必须通过；lint/typecheck 必须通过或说明既有基线问题。
2. 新增/修改逻辑必须有自动化测试；关键路径必须有回归测试。
3. 无法运行测试时必须说明原因并标 BLOCKED，不得声称通过。
4. API 变更需契约测试或至少请求/响应兼容性验证。
5. 数据模型变更需迁移脚本、回滚方案、旧数据兼容策略。
6. 用户可见变更需验收步骤；真机/凭据/法务事项无法完成标 BLOCKED。
7. CI 未过不得合并；无 CI 时必须在本地执行等价命令并记录。
8. 性能敏感路径不得引入明显回归；如有影响需给出测量或说明。
9. 安全底线：输入校验、鉴权/授权、IDOR、路径穿越、ReDoS、敏感日志、秘密管理必须检查。
10. 隐私底线：最小化采集、脱敏、明确同意；不得在日志/推送/测试数据中泄露病历信息。

## 4. 代码与版本控制
- 分支命名：`task/<任务号>-<简述>`；提交信息：`<任务号>: <动词> <对象>`。
- 一个 commit 只做一件事；禁止“大杂烩”提交。
- 不提交生成物、临时文件、调试代码、真实凭据。
- 不强制覆盖率数字，但关键路径必须有测试；新增逻辑尽量覆盖。
- 代码审查：无法人工 review 时，必须提供 self-review checklist：正确性、边界、错误处理、安全、测试、兼容、回滚。
- 文档：设计决策用 ADR；用户可见变更更新变更日志；运维相关更新运行手册。

## 5. 数据、API 与兼容
- API 变更遵循语义化版本；尽量向后兼容；破坏性变更单独任务并给迁移窗口。
- 数据库迁移提供 up/down 或补偿脚本；修复脚本幂等；不得静默覆盖用户数据。
- 客户端与服务端契约变更需同步更新类型/客户端 SDK/测试。
- 跨端同步/缓存变更必须说明一致性、冲突处理、重复恢复行为。
- 解析 Skill/规则变更需回归样例，避免影响既有医院模板。

## 6. 安全、隐私与合规
- 不引入新的明文存储敏感数据；PC Web 明文 localStorage 问题不得扩大。
- 日志、错误信息、推送 payload 不含病历/检验/用药等敏感信息。
- 新增接口必须有鉴权/授权与最小披露；授权范围不得扩大。
- 文件上传/解析路径必须防路径穿越、魔数校验、大小限制、ReDoS。
- 合规相关文案明确“非诊断、非治疗建议”；不得给出个体化医疗建议。
- 涉及法务/DPIA/知情同意的交付物标 BLOCKED，等待人工确认。

## 9. 冲突与暂停规则
出现以下情况必须暂停并询问，不得自行决定：
- 代码与 PRD V1.1 冲突
- 需求不明确或验收标准缺失
- 需要破坏性 API/数据模型变更
- 需要真实凭据、真机、法务审核
- 测试无法运行且无法给出替代验证
- 后续计划与当前任务边界冲突
- 任何可能泄露患者数据或扩大授权范围
