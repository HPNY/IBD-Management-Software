## [S1] Problem

worklist **T6.4**「V2 扩展：饮食 / 药物评价 / 同城病友 / AI 分析」是一条未拆分的巨型项，无法按会话开工或验收。PRD §2.7.6–2.7.7、§5.2/5.4/5.5 定义了四类能力，但实现深度、隐私边界与先后关系未固定。需要**可独立验收的子包任务清单**，使四轨可并行推进，且与 local-first / T6.1 Skill 社区 / T6.2 医生端边界不重叠。

已有基础：G6 已交付食物标签日志 + 食物×排便关联观察（`food_logs` v7、`FoodStoolPage`）；发作预警为规则型；无 DrugReview / GeoGroup / AI 分析实现。

## [S2] Design — 四轨并行子包

**总原则**
- 四轨 **D1–D4 并行**，互不依赖；顺序由资源决定。
- **local-first 优先**：D1 / D4 尽量纯本地；D2 / D3 涉及他人数据才上云/社区，且匿名、默认不上传病历。
- 每子包 3–6 个最小可验收任务；单包内任务可串行或并行，见 `depends`。
- 不含 T6.1 Skill 社区、T6.2 医生端、推送/真机项。
- 每个子包完成后应单独开 compose 立项实施；本 spec 为权威拆解，不改 PRD 正文。

### S2.2 D2 · 药物评价社区（匿名）

**目标**：PRD §2.7.6 疗效/副作用评价；按药聚合。**不含可识别病历**；匿名昵称+IBD 类型（CD/UC）。

**隐私契约**：上传字段仅 `drugName`、`ibdType`、`efficacy(1-5)`、`seSideEffect(0-3)`、`sideEffectTypes[]`、`stillUsing`、`comment`（用户主动填写）、匿名 `userId`（app_user_uuid 哈希）。禁止上传检验值、PDF、症状日记全文。

### S2.3 D3 · 同城病友 + 就诊指南

**目标**：PRD §2.7.7。地理匹配 + 匿名群组 + 城市就诊指南。**不显示真实姓名/精确住址**；城市级定位。

**隐私契约**：仅存 `city`（可手动选，不必 GPS）；群组消息不端到端加密则默认「论坛式公开匿名帖」，需在 UI 写明。精确位置禁止入库。

### S2.4 D4 · AI 辅助分析（可先规则版）

**目标**：PRD §5.2 活动趋势预测、异常指标预警、用药效果评估。**一期可规则/统计实现**，LLM 可选后置。

**契约**：结论标注「仅供参考」；异常不自动外发；LLM 若接入须可关、默认关，且病历明文出站需单独同意（对齐 local-first B 类）。

| ID | 任务 | 验收（covers） | depends |
|----|------|----------------|---------|
