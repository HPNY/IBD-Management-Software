## [S1] Problem

当前 MVP 把 **Postgres 当权威存储**：检验/用药/注射/症状默认写库，JWT 登录为强制门槛。这与两条产品原则冲突：

1. **个人医疗数据默认只存本机，未得到用户授权不得上传**  
2. **App 是个人终端应用**：默认用应用内标识，**不强制登录**

需要把权威数据迁回设备，服务端降级为「可选能力」（云端 AI 解析、可选同步/备份、Skill 社区、医生端），并重新划分「永不上传 / 授权后上传 / 可匿名上云」边界。

## [S2] Design — 原则与目标架构

### S2.1 硬约束

| 约束 | 含义 |
|------|------|
| 本地权威 | 病程事实源在 App 本地 DB（Drift/SQLite）；服务端无默认副本 |
| 默认离线 | 无网络可完成：记症状、记用药、看历史、看已下载报告 |
| 最小上传 | 仅在用户对**单次操作**明确同意后上传；可随时「关同步 / 删云端」 |
| 无强制登录 | 首启生成 `app_user_uuid`，无需手机号/微信即可用满核心功能 |
| 可迁移优先 | 换机靠「本地导出 + 用户自选云备份 / 手工导入」，不靠设备硬件 ID |

### S2.2 目标架构

```text
┌─────────────────────────────────────────────┐
│                 Flutter App                  │
│  app_user_uuid（本地生成，非 IMEI/IDFA）      │
│  Drift/SQLite：患者、检验、用药、注射、症状…  │
│  本地加密（SQLCipher / 字段级）               │
│  本地提醒（flutter_local_notifications）      │
└───────────────┬─────────────────────────────┘
                │ 仅授权时
                ▼
     ┌──────────────────────┐
     │  可选云端能力（Opt-in） │
     │  ① 单次 PDF 解析      │ ← 临时上传，可「用完即删」
     │  ② 可选同步/备份      │ ← 用户开关 + 端到端加密
     │  ③ Skill 社区/医生端  │ ← 显式分享，不含原始病历默认集
     └──────────────────────┘
```

服务端角色从「主库」变为：

- **Parse Worker**：有网且用户点「AI 解析」时的可选算力  
- **同步服务**：用户打开同步后的多设备副本（非权威）  
- **社区/医生端**：分享与授权查看  

### S2.3 数据分类（上传策略）

| 类别 | 例子 | 默认 | 授权后 |
|------|------|------|--------|
| A 病程本体 | 检验值、日记、用药、手术文字、原始 PDF | **永不自动上传** | 仅「同步/备份」开关开启后加密上传 |
| B 解析任务 | 本次 PDF 字节 | 本地 | 「AI 解析」单次同意；支持解析后删除原件 |
| C 派生模板 | ParseSkill 正则 JSON | 可本地生成 | 可匿名贡献社区（去掉医院病历字段） |
| D 诊断崩溃 | 崩溃堆栈、性能 | 可选 | 默认关，设置里打开 |

### S2.4 身份模型

| 模式 | 标识 | 服务端 |
|------|------|--------|
| 本地（默认） | `app_user_uuid`（首启 randomUUID，存本地） | 不要求账号 |
| 同步/备份（可选） | 同一 uuid + 用户**关联手机号**后签发短时凭证 | 恢复与多端密钥 |
| 医生端 | 患者扫码授权，短期凭证 | 只读授权子集 |

**产品原则（用户明确）**：不要做「登录/注册」体感。云能力只提供可选**关联手机号**（换机恢复、多端密文同步），入口与文案必须强调「病历在本机，未授权不上传」。规避真实登录墙。

**禁止**：IMEI、IDFA、ANDROID_ID 作为用户主键；禁止把核心功能做进登录门禁。

## [S3] 改动面清单

### A. App（Flutter）— 主战场

| 模块 | 改动 | 优先级 |
|------|------|--------|
| 本地库 | 引入 **Drift**：schema 与 API 实体对齐（lab/med/injection/symptom/parse_job/…） | P0 |
| 身份 | `LocalIdentityService`：生成/持久化 `app_user_uuid`；不做登录墙，仅可选「关联手机号」 | P0 |
| 鉴权 | 业务页改为读本地库；去掉「未登录 401 门禁」 | P0 |
| 检验录入/直传解析 | 先写本地；上传 PDF 需单独确认弹窗 | P0 |
| 解析结果 | 落本地 labs；Skill 可在本地由确认结果生成 | P0 |
| 用药/注射/症状 | 全量本地 CRUD；注射提醒用本地通知 | P0 |
| 加密 | SQLCipher 或敏感字段 AES；密钥放 Keystore/Keychain | P1 |
| 同步开关 | 设置页：关闭时零网络；开启才绑账号 + 增量同步 | P1 |
| 导出/导入 | JSON 导出（用户发起）；换机导入 | P1 |
| 云端解析 | 「用 AI 解析」授权流 + 解析后删除云端原件选项 | P1 |

### B. 服务端（Nest / Worker）

| 模块 | 改动 | 优先级 |
|------|------|--------|
| 默认策略 | 文档与部署默认 **不要求登录即可解析**；病历写库仅 sync 路径 | P0 |
| Parse API | 「匿名/会话上传」：短时上传令牌（TTL），可不绑长期账号 | P1 |
| 同步 API | 以 `app_user_uuid` + 绑定账号做端到端密文同步；服务端不解密病历 | P1 |
| 实体保留 | labs/meds 等表保留，但语义改为「云副本」非权威 | P1 |
| Skill 社区 | 只收 Skill JSON，不收原始报告 | P2 |
| 医生端 | 授权子集 + 审计 | P2 |

### C. 文档 / 合规

- 更新架构 spec：本地权威 + 可选同步  
- 隐私说明：收集什么、何时上传、如何删除云端数据  
- 默认关闭分析/崩溃上报
