01结论先行

先说值得保留的部分——这不是一次推倒重来，而是在已有方向上补齐系统性与可用性。

值得保留

隐私即界面的表达方式

首页「数据仅存本机，未授权不上传」常驻条、解析前的同意弹窗、设置页的密文说明——把合规做成了可见的产品语言，而不是藏在文档里。这是本产品最有辨识度的设计资产。

值得保留

医疗色彩的克制

teal 主色避开了"医院蓝"的冷硬，也避开了健康类 App 常见的橙色焦虑营销。20px 大圆角 + 极淡描边（4% 黑）的卡片体系方向正确。

必须修

设计令牌没有穿透到页面

75 个文件里只有 6 个用 Theme.of(context)，13 个文件硬编码 Color(0x…)，圆角出现 8 种不同取值。改一次主色要改 20 处，这不是设计系统，是设计约定。

必须修

暗色模式是"假开关"

主题里定义了 buildIbdDarkTheme()，但页面全部硬编码 IbdColors.card（白）与 IbdColors.textPrimary（深）。暗色下深字压深卡，实测对比度 1.07:1——不是不好看，是看不见。

必须修

打卡页把"完整"当成了"好用"

11 张同权重卡片纵向堆叠、1633 行代码、保存按钮在屏幕之外约 4 屏处。而患者真实场景是：厕所门口、单手、30 秒内、身体不适。表单的完整性和完成率在这里是负相关。

必须修

无障碍停留在设置开关

全仓 Semantics 使用数为 0；严重度日历、疾病活动度灯只用颜色编码（红/绿/灰）；"简洁模式"开启后只隐藏了一条隐私横幅——文案承诺了"只显核心指标"，代码没有兑现。

03现状诊断

每条问题都附代码位置与实测数据，便于直接排期修复。

P0设计令牌断层：8 种圆角、13 处硬编码色A1

主题层定义了完整的 IbdColors，但页面层大量绕开它。结果是"同一个卡片"在不同页面半径不同、"同一个标题"字号不同，视觉一致性靠人肉记忆维持。

区块标题实现4 套并存：IbdSectionTitle / _SectionCard / textTheme.titleSmall / 裸 Text
令牌包状态packages/ui-tokens 仅有 package.json（description: "设计令牌占位"），无 src、无任何引用

也就是说，令牌这件事被规划过、建过目录，但没有落地——这比"没想到"更值得优先处理，因为占位包会给人"已有设计系统"的错觉。

// dashboard_tab.dart:604 vs analysis_tab.dart:195 vs theme.dart:49 Container(color: IbdColors.card, borderRadius: circular(20)) // 首页卡片 Material(color: IbdColors.card, borderRadius: circular(20)) // 分析卡片 CardThemeData(shape: circular(20)) // 主题卡片 // 但 symptom_page.dart:1284 用 20，lab_entry 用 12，settings 用 16 —— 四套并存
P0暗色模式不可用：深字压深卡，对比度 1.07:1A2

main.dart 里 themeMode: ThemeMode.system 让暗色模式真的会触发，但页面用 IbdColors.card（#FFFFFF）当卡片底色、IbdColors.textPrimary（#0F172A）当正文色——这两个都是浅色模式的常量，不会随主题切换。

// 暗色主题：card = #151E2E // 页面实际绘制：container #FFFFFF + text #0F172A // 结果：白卡片 → 视觉刺眼；若卡片随主题变深，则 #0F172A on #151E2E = 1.07:1（不可读）

根因不是配色，是取值路径。修法是让页面取 Theme.of(context).colorScheme.surface / onSurface，而不是 IbdColors.xxx 常量。

P0对比度不达标：主按钮文字 3.74:1、成功色 2.54:1A3

按 WCAG 2.1 AA（正文 4.5:1，大字号/图形 3:1）实测，当前配色有 6 处不达标。医疗场景中低视力用户比例显著高于一般人群，这不是"可以后补"的项。

P0打卡页：11 张卡片、4 屏滚动、保存按钮在最末A4

症状打卡是全产品使用频次最高、也最需要"低摩擦"的页面，但它的结构是：快捷模板 → 症状日历 → 腹痛 → 排便次数 → 腹泻次数 → Bristol（7 个选项各占一行）→ 便血 → 紧迫/黏液/恶心 → 疲劳/腹胀 → 肠外表现 → 睡眠/压力 → 整体感受 → 保存。

三个具体代价：① 无进度感，用户不知道"还有多少"；② 保存按钮在 ~4 屏之后，中途退出即丢失（_saved 只在内存里）；③ 所有卡片同一视觉权重，必填与选填无从区分。

// symptom_page.dart 1633 行 / 11 个 _SectionCard / 保存按钮位于 ListView 最后一个 child（1234 行） 无 Form / 无草稿持久化 / 无分步 / 无"必填"标记
P1分析 Tab：15 个入口平铺成一列A5

analysis_tab.dart 把趋势、时间线、检查手术、排便、食物、就诊摘要、发作预警、AI 分析、药物评价、同城病友、我的医生、量表、年报、导出全部做成同款 _NavCard，14 项首尾相连。后果：高频功能（趋势/摘要）与低频功能（药物评价/同城）视觉权重相同，用户找不到东西。

同时存在语义重叠：「发作预警」与「AI / 规则分析」、「年度报告」与「就诊摘要」、「排便细表」与「食物与排便」——四组功能边界在界面上不可区分。

P1状态设计缺失：静默失败、纯文本空态、无骨架屏A6

首页 _loadStats() 的异常被 catch (_) {} 整体吞掉。数据库读失败时，用户看到的是"检验记录 0、注射无待打针"——错误被渲染成了"你很健康"。这在医疗产品里是最高风险的一类缺陷。

// dashboard_tab.dart:96 } catch (_) {} // 失败 → 统计值保持 0 → 界面呈现为"一切正常" // 空态实现（app.js:188） root.innerHTML = `<div class="empty">暂无套餐，点右上角「新建套餐」</div>`; // 纯文本，无 CTA

全仓 CircularProgressIndicator + "暂无" 共 41 处，全部为居中转圈或单行灰字，没有骨架屏、没有插图、没有引导动作。

P1无障碍：0 处 Semantics、纯颜色编码、固定宽高比A7

① 语义缺失：全仓 Semantics() 使用数为 0。自绘的 InkWell + Container（模块卡、Bristol 选项、严重度日历格）对读屏器只暴露为无标签可点区域。

② 纯颜色编码：首页"疾病活动度"三灯只有红/绿/灰圆点 + CRP/ESR/钙卫 文字，状态靠颜色区分；症状日历同理。红绿色盲（男性约 8%）无法读取。

③ 大字体失效：AccessibilityPrefs.textScale = 1.25 全局生效，但 GridView childAspectRatio: 1.15、NavigationBar height: 64 都是写死的，放大后 4 宫格卡片文字会溢出。

④ 简洁模式未兑现：simpleMode 全仓仅 1 处消费（首页隐藏隐私条），而设置页文案承诺"首页只显核心指标与今日待办"。

P1PC Web 工具：9 个按钮平铺、7 列不换行、无脏状态A8

工具栏把「新建 / 复制 / 删除 / 导入 / 导出 JSON / 导出 Dart / 重置默认 / 保存」放进同一行同一视觉级别，破坏性操作"删除套餐"紧邻"复制"，且无二次确认、无撤销。表格 7 列全部 white-space: nowrap，窄屏只能横向滚动。顶部还有一行 AI生成 水印文案直接渲染在界面里。

// styles.css:207 th, td { padding: 10px 12px; white-space: nowrap; } // 7 列 → 必然横向溢出 // index.html:11 <p data-aigc-mark="1">AI生成</p> // 构建水印泄漏到 UI

另外 index.html 里混用内联 style（第 40、48 行），.btn.danger 只有文字变色没有底色区分，保存成功后仅靠 toast 提示、无持久"已保存"状态。

P2排版细节：字体回退、数字不对齐、6 档字重A9

fontFamily: 'PingFang SC' 单值指定——Android 上不存在该字体，会整体回退到系统默认，导致两端字距与行高不一致。字重出现 w600 / w650 / w700 / w750 / w800 五档（Flutter 实际只支持 100 的整数倍，w650/w750 会被吸附，视觉不可控）。检验数值全部用比例字体，小数点不对齐，纵向扫读困难。

04设计令牌 v2

原则：语义层命名 + 双轨明暗 + 可测对比度。页面只允许引用语义令牌，禁止出现十六进制字面量（可用 lint 规则强制）。

4.1 色彩：把"品牌色"和"可用色"分开

  • 三段式进度：核心 3 项（腹痛 / 排便 / 便血）→ 细节 → 生活。首屏完成即"有效记录"，其余可选。

07无障碍与暗色专项

这两项在医疗产品里不是"加分项"，是准入门槛：IBD 患者中老年与低视力比例高，且大量使用发生在身体不适状态。

7.1 四项强制改造

项目做法验收
语义标签 给自绘可点区域补 Semantics(button: true, label: …)；严重度日历每格补 label: "11月8日，重度 7.2 分"；数值补 value 与 increasedValue TalkBack 走查 5 个主流程，每个可点元素都有可读标签
非颜色编码 活动度灯 = 圆点 + 文字（正常/偏高/未测）；严重度日历 = 色块 + 数值或图案（轻/中/重字符）；chip 选中 = 填充 + 勾 灰度截图下仍能区分三种状态
字号自适应 去掉固定 childAspectRatio，改 Wrap 或 IntrinsicHeight；NavigationBar height 随 textScaler 计算；所有单行文案允许 2 行 1.25× 与 1.5× 下无溢出（flutter test 加 golden）
点击区 ≥ 44×44 _icon-btn 当前 padding 4/8，实测约 28×26；统一提到 44 或用 MaterialTapTargetSize.padded DevTools 检查最小命中区

7.2 暗色模式：改"取值路径"而不是"再加一套颜色"

正确做法不是给每个页面写 isDark ? A : B，而是把页面里的常量全部换成主题取色，暗色自然成立。改造后 buildIbdDarkTheme() 只需补齐 inputDecorationTheme、filledButtonTheme、navigationBarTheme 三项——目前暗色主题只定义了 appBar 和 card，其余全靠默认值。

// 改造前 color: IbdColors.card, // 永远白 color: IbdColors.textPrimary, // 永远 #0F172A // 改造后 color: Theme.of(context).colorScheme.surface, color: Theme.of(context).colorScheme.onSurface, // 或统一封装：context.ibd.surface / context.ibd.textPrimary（内部按 brightness 分支）
风险提示：若暂时不打算支持暗色，应立即把 themeMode 改为 ThemeMode.light 并从设置中移除相关入口——一个不可用的暗色模式，比没有暗色模式更伤信任，尤其在医疗场景。

09落地路线

按"风险 × 改动成本"排序。P0 是信任与可用性风险，必须先做；P2 是体验增益，可并行排期。

P0 · 第 1 周

止血：让现有界面不出错

  • 首页 catch (_) {} → 错误态 + 重试
  • 暗色模式二选一：修好 或 关掉
  • 6 处对比度不达标配色替换
  • 打卡页加底部吸附保存 + 草稿持久化
  • Web 删除加二次确认 + 撤销
  • 移除 AI生成 水印
目标：不再出现"数据读失败却显示 0"和"暗色下看不清"两类事故。
P1 · 第 2–3 周

立系统：令牌与组件收敛

  • 落地 IbdTokens + context.ibd 扩展
  • 7 个基础组件替换 4 套重复实现
  • 圆角/间距/字重收敛到 4/7/3 档
  • 首页改版（一句话状态 + 主行动 + 指标带）
  • 打卡页三段式 + 必填/选填分层
  • 加 custom_lint 禁止硬编码色值
目标：features/ 下 Color(0x 归零，卡片实现唯一。
P2 · 第 4–6 周

提体验：信息架构与无障碍

  • 分析 Tab 四组分层 + 三组合并
  • 语义标签全覆盖 + 非颜色编码
  • 骨架屏替换居中转圈
  • 简洁模式真正落地（按 PRD 承诺）
  • 1.25×/1.5× golden 测试
  • Web 工具栏分组 + 键盘快捷键
目标：TalkBack 可完成打卡主流程；灰度下可辨状态。
