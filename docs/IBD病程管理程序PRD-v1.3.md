## 一、产品概述

### 1.1 产品名称
**IBDers** — IBD患者病程自我管理平台

### 1.2 产品定位
面向炎症性肠病（IBD，含克罗恩病和溃疡性结肠炎）患者的**病程记录与自我管理工具**，帮助患者系统化管理检验数据、用药记录、检查影像、注射排期等全病程信息，辅助医患沟通和治疗决策。

### 1.3 目标用户
- **核心用户**：确诊IBD的患者（克罗恩病、溃疡性结肠炎）
- **扩展用户**：患者家属/照护者、消化内科医生（查看患者自管数据）

### 1.4 产品背景
IBD是慢性病，患者需要终身管理。以一位典型克罗恩病患者的经历为例：

```
确诊 → 药物治疗 → 应答不佳换药 → 手术 → 术后恢复 → 多次方案调整
     → 生物制剂注射 → 定期检验复查 → 影像/内镜随访
```

这个过程中，患者面临的信息管理痛点：
- **检验报告分散**：纸质报告、PDF、医院APP，数据碎片化
- **指标趋势难追踪**：CRP、钙卫蛋白、血沉等关键指标跨年度对比困难
- **用药历史复杂**：多种药物、剂量调整、停药原因需要完整记录
- **注射排期易遗漏**：生物制剂有严格的注射时间窗口
- **医患信息不对称**：患者难以向医生清晰呈现完整病史

### 1.5 产品边界与事实口径

#### 1.5.1 产品边界（只记录、只提醒、只描述）

本产品是**病程记录与自我管理工具**，不是诊断或治疗工具。全产品遵守以下边界：

1. **只记录**：记录患者自述症状、检验/检查报告、用药与注射、就诊事件；不生成新的医学结论。
2. **只提醒**：按日期或明确阈值提醒"该复查/该注射/该核对"；提醒文案只陈述事实与时间，不给治疗指令。
3. **只描述趋势**：展示数值、方向与阈值线，不判断"好转/加重/达标"，不输出"建议用药/停药/加量/减量"。
4. **不写诊断结论、不写治疗建议、不自动改写医嘱**：任何医嘱/预约以医生出具的最新记录为准，产品只做记录与校验（§2.2.3）。
5. **例外**：出现红旗症状（便血、剧烈腹痛等）时，只提示"请尽快联系医生/就医"，不解释病因、不给处置方案。

#### 1.5.2 三层事实口径（本文全部状态标注的含义）

| 状态 | 含义 | 判定依据 |

##### 引擎一：Skill模板解析（快速通道）

**核心理念**：每家医院的报告格式是固定的，首次解析后生成Skill模板，后续同类报告直接套用模板提取，速度更快、准确率更高。

**Skill模板内容**（✅ 已实现主体；`check_fn`/`multiline` 见下方注记）：
```yaml
hospital: 某三甲医院A
report_type: 血常规（五分类）
version: 1.2
last_updated: YYYY-MM-DD

# 日期提取规则（优先级自上而下，命中即停；须记录 date_source）
# ✅ 已实现：primary + fallback（2 级）
# ⚠️ V1.3 新增口径：fallback_2（报告时间）、fallback_3（文件名兜底）尚未实现
date_extraction:
  primary: '(20\d{6})G\d+'                                    # 1. 样本号（8 位日期）
  fallback: '采集日期[:：]\s*(\d{4}[/-]\d{1,2}[/-]\d{1,2})'      # 2. 采集日期
  fallback_2: '报告时间[:：]\s*(\d{4}[/-]\d{1,2}[/-]\d{1,2})'    # 3. 报告时间（只取日期，忽略时分）
  fallback_3: '文件名日期 (\d{4})[.\-/](\d{1,2})[.\-/](\d{1,2})'  # 4. 文件名兜底
  date_source: sample | collected | reported | filename          # 命中哪一级（用于追溯）

# 项目提取规则
items:
  - name: 白细胞计数
    alias: WBC
    pattern: '白细胞计数\s+([\d.]+)'
    multiline: true  # ⚠️ 字段可存储，但解析引擎暂不执行跨行逻辑
    unit: '10^9/L'
    ref_range: [3.5, 9.5]   # 仅默认值
    ref_source: mapping     # 🧩 PDF 有参考范围时以 PDF 为准（pdf），缺失才用映射默认（mapping）→ 未实现
    value_operator: null    # 🧩 纯数值为 null；">"/"<"/"a-b" 等保留形式，不强行转数值 → 未实现
    qualitative: false      # 🧩 定性指标保存原文，不参与数值比较 → 未实现
    check_fn: 'v < 3.5 or v > 9.5'   # ❌ 未实现；异常判定实际按 ref_range 数值比较

  - name: 血红蛋白
    alias: Hb
    pattern: '血红蛋白\s+([\d.]+)'
    unit: 'g/L'
    ref_range: [130, 175]
    ref_source: mapping
    value_operator: null
    qualitative: false

  # ... 更多项目（完整指标字典见 §2.1.7）

# 特殊处理规则（⚠️ 已实现：仅 patient_id_mismatch / crp_multiline 两种硬编码规则）
special_rules:
  - filter: 'patient_id_mismatch'  # 病案号误匹配过滤（候选值等于病案号时跳过）
  - filter: 'crp_multiline'        # CRP 跨行处理（逐行匹配后检查下一行数值）

# 🧩 V1.3 新增口径（Skill 侧已验证，引擎待实现；详见 §2.1.7）
matching_rules:
  exclude_map:            # 包含匹配前必须先排除冲突词
    P:    ['碱性磷酸酶']
    CA:   ['粪便钙卫蛋白']
    CR:   ['肌酸激酶']
    ALB:  ['白蛋白/球蛋白比值', '球蛋白', '前白蛋白']
    TBIL: ['直接胆红素', '间接胆红素']
  value_rule: '纯数值优先作为结果值；<X / >X / a-b 形式优先归参考范围；无法区分时进待核对，不猜'
  method_words: ['利德曼直接法', '免疫比浊法', '计算法', '速率法']   # 检测方法词跳过，不参与取值
```

##### 引擎二：AI智能解析（通用兜底）

**适用场景**：
- 首次遇到的医院报告格式（无Skill模板）
- 图片型/扫描型PDF（多模态大模型识别）
- 格式特殊的报告（非标准排版；**手写批注识别暂不支持** ❌）

**AI解析流程**（✅ 已实现，Vision 依赖多模态模型配置）：

| 步骤 | 处理方式 | 说明 |
|------|---------|------|
| 1. PDF读取 | pymupdf | 文字型PDF直接提取文本；文本不足 40 字符的页视为扫描件，3x 缩放栅格化为图像 |
| 2. 文本/图像理解 | 大语言模型（OpenAI 兼容接口，≤4 页图像送模） | 输入原始文本或图像，AI理解报告结构和内容 |
| 3. 结构化提取 | AI + 规则校验 | 输出标准化JSON（项目名/数值/单位/参考范围） |
| 4. 异常标注 | 规则引擎 | 根据参考范围自动标注 ↑/↓ |
| 5. 结果确认 | 用户交互 | 用户确认/修正提取结果，修正反馈回 Skill |

**AI Prompt设计示例**（✅ 与实现同源）：
```
你是一名医学检验报告解析助手。请从以下检验报告文本中提取所有检验项目，
返回JSON格式，包含以下字段：
- name: 项目中文名称
- value: 数值结果（纯数值；无法数值化时置 null）
- value_raw: 报告原文（如 ">90"、"阴性"）
- value_operator: 运算符（null / "<" / ">" / "~"）
- qualitative: 是否定性指标（true/false）
- unit: 单位
- ref_min: 参考范围下限（如有；优先取 PDF 原文）
- ref_max: 参考范围上限（如有；优先取 PDF 原文）
- ref_source: 参考范围来源（pdf / mapping）
- flag: 异常标记（↑/↓/null）

特别注意：
1. 有些报告的项目名和数值分两行显示，请识别关联
2. 过滤掉病案号、样本号等非检验数值
3. 区分">1800"这样的上限值和具体数值

报告文本：
{report_text}
```

##### 双引擎协作机制

| 场景 | 处理路径 | 速度 | 准确率 |
|------|---------|------|--------|
| 已有Skill模板 | 模板解析 → 输出 | 极快（<1s） | 极高（99%+） |
| 首次该医院报告 | AI解析 → 用户确认 → 生成Skill | 较慢（3-5s） | 高（95%+） |
| 图片型PDF | Vision AI → 用户确认 | 较慢（5-10s） | 中高（90%+） |
| Skill解析失败 | 降级到AI解析 → 更新Skill | 中等 | 高 |

> ⚠️ 上表速度/准确率为**设计目标**，当前无实测统计；AI 路径受大模型响应影响（默认超时 60s），无 <5s 保证，详见 §4.3。

**Skill自动生成/更新逻辑**（⚠️ 部分实现）：
1. 用户上传PDF，无匹配Skill → AI解析 → 用户确认 → **自动生成新Skill** ✅
2. 用户上传PDF，Skill解析成功但遗漏字段 → AI补全 → 用户确认 → **自动更新Skill版本** ❌（Skill 有命中即返回，无 AI 补全环节）
3. 用户手动修正AI/Skill解析结果 → **将修正反馈回Skill** ✅
4. 用户在不同医院检查 → 按医院（+报告类型）分键维护独立Skill ✅

**输出格式**（⚠️ 部分实现）：
- 中文项目名称（非英文缩写）✅
- 按时间排列的结构化数据表 ✅
- 异常值用 ↑↓ 标注 ✅（优先采用 PDF 报告箭头；无箭头时按报告参考范围判断）
- 数据来源标记（Skill解析/AI解析/手动录入）✅ 如实写入（T2：confirm 按真实引擎、App 三档；旧数据不回填）
- **存储与展示分离（V1.3 口径）**：落库为"检验头表 + 指标明细"**长表**（当前实现，见 §3.2）；**宽表仅用于展示/导出**——列＝核心指标 ∪ 历史出现过的可选指标，某次未测留空，不按单份报告动态删列；新增可选指标时整表补列。
- **指标级追溯字段 `confidence` / `aliases_hit` / `ref_source` / `value_operator` 为 V1.3 新增需求**，当前未落库（见 §3.1）。

#### 2.1.3 指标趋势分析
**功能描述**：以图表形式展示关键指标的时间趋势。

**IBD核心指标面板**（✅ 已实现首屏 7 项；完整指标字典见 §2.1.7）：

| 指标 | 展示口径（示例默认值，以报告单为准） | 临床意义 | 状态 |
|------|---------|---------|------|
| 超敏C反应蛋白 | 按报告参考范围（示例 <5.0 mg/L） | 全身炎症活动度 | ✅ |
| 血沉 | 按报告参考范围（示例 <15 mm/h） | 炎症活动度（滞后指标） | ✅ |

> **V1.3 口径修正（重要）**：
> - 粪便钙卫蛋白**不存在统一参考范围**：不同试剂/实验室界值不同（本机浙大二院报告单为 `<200 μg/g`，代码 `lab_panels.dart:69,172` 的默认值即来源于该报告）。**200 μg/g 不是通用缓解线，也不是 AGA 指南阈值**——AGA 2023 在"症状缓解 + 近期内镜缓解"场景用 **<150 μg/g** 排除活动性炎症（Conditional，低-中确定性），术后低危用 <50；综述把 100–250 μg/g 视为需复测的灰区。

#### 2.1.5 检查/影像报告 PDF 解析（🧩 Skill 侧已跑通、产品待实现）

**现状（2026-11-02）**：App/服务端**无检查解析管线**——`services/parse-worker` 只有检验一条路径，`services/api` 无 examination 模块，检查记录仅存于 App 本地表。Skill 侧已完成解析试跑，但**未做产品化落库与界面**。

**解析流程（产品化目标）**：
1. **文字型/图片型判定**：文字型直接抽文本；文本不足 40 字符的页按扫描件处理，3× 栅格化后走多模态识别。
2. **检查类型识别**：肠镜 / MRI小肠造影 / CTE / 病理 / 超声彩超 / 其他。
3. **日期提取优先级**（命中即停）：`检查日期` > `报告日期` > `报告时间`（只取日期）> 样本号/超声号中的日期 > 文件名日期；均未命中 → 进待核对队列。
4. **字段提取**：机构、关键结论（原文摘录，不改写）、活动度评分（肠镜 SES-CD / 超声 IBUS-SAS 原文）、报告路径。
5. **写入**：按"日期 + 类型"去重（同日期同类型视为更新）；合并/分条规则见 §2.1.4。
6. **失败处理**：关键结论缺失或解析失败 → 进待核对队列（§2.1.6），不静默写入。

**报告留存策略（与"用完即删"的关系）**：
- 检查类报告默认**保留报告路径/索引**（用于复诊回溯与年报复核），原件删除遵循用户授权与 §4.1；删除原件**不删除**已处理清单、去重键与结构化解结果。
- 当前该策略**未实现**（无报告路径字段、无检查类原件策略）。

**验收口径**：同一份肠镜报告重复上传 → 不新增检查记录；关键结论缺失 → 待核对队列出现该文件。

#### 2.1.6 解析核对、去重与处理清单（❌ 未实现；🧩 Skill 侧已跑通）

**现状**：服务端 `parse_jobs.status` 存在 `awaiting_review` 枚举但**从未赋值**；无人工核对队列、无客户端"已处理清单"、无任何 PDF/检验去重（`enqueue`、`confirm`、App 本地保存均直接新增）。

**2.1.6.1 待核对队列**（解析失败或关键字段缺失时进入）：

| 字段 | 说明 |
|---|---|
| 文件名 / PDF 路径 | 来源定位 |
| 已识别字段 | 便于人工补录 |
| 缺失字段 | 例：日期未识别 / 缺关键结论 / 指标全未解析 |

判定规则（与 Skill 一致）：**检验**——"日期 + 至少一个核心或可选指标"即可写入；日期缺失或一个指标都未解析出才进队列。**检查**——日期、类型、关键结论三项齐全才写入，任一缺失进队列。

| 字段 | 说明 |
|---|---|
| 文件名 / 文件大小 | 文件大小用于识别"同名但内容更新" |
| 日期 / 类型 | 检验 / 检查 |
| 去重键 | 检验＝日期+项目；检查＝日期+类型 |
| 处理日期 / 状态 | `done` / `updated` / `skipped_duplicate` / `failed` / `pending` |

**2.1.6.3 去重规则**：
- 检验：同日期同项目 → 更新该行，不新增；不同项目 → 追加。
- 检查：同日期同类型 → 视为更新。
- 同名文件：文件大小或去重键变化即视为新文件；两者都一致才判重复。
- 重复上传落 `skipped_duplicate` 并提示，不静默丢弃。

**2.1.6.4 与"用完即删"的关系**：删除云端原件不得删除清单、去重键与核对状态（否则无法判断"这份报告是否处理过"）。

**匹配与排除规则（🧩 Skill 侧已验证，产品待实现）**：
1. 别名命中优先**精确匹配**，其次**包含匹配**；包含匹配必须先排除冲突词。
2. 冲突排除：磷↔碱性磷酸酶；钙↔粪便钙卫蛋白；肌酐↔肌酸激酶；白蛋白↔白蛋白/球蛋白比值、球蛋白、前白蛋白；总胆红素↔直接/间接胆红素；总蛋白↔白蛋白、球蛋白、前白蛋白、铁蛋白；γ-谷氨酰转肽酶↔谷丙/谷草转氨酶。

4. **取值规则**：纯数值优先作为结果值；`<X`/`>X`/`a-b` 优先归参考范围；检测方法词（如"利德曼直接法""免疫比浊法""计算法""速率法"）跳过；行内多个纯数值且无法用参考范围区分时进待核对，不猜。
5. 特殊值 `<0.5`、`>90` 等保留原文；定性指标（如粪便隐血）按报告原文记录，不做数值比较。

**功能描述**：定期评估疾病对生活质量的整体影响。

**评估量表**（⚠️ 量表齐全，但计分口径须按 V1.3 修正）：
- **SF-36（非授权简化版）** ⚠️ 36 题、统一 0–4 锚点、自算 8 维 0–100；**条目为改写版、域映射与标准不同（实现 GH1/PF8/RP5/BP2/VT4/SF5/RE5/MH5，标准为 GH5/PF10/RP4/BP2/VT4/SF2/RE3/MH5）、无反向计分、无 PCS/MCS**。因此 0–100 域分**不可与标准 SF-36/RAND-36 常模或文献分数对照**；UI/导出不得用"SF-36 得分"暗示标准分，建议命名"生活质量自评（简化版）"。

**应用场景**：

## 四、非功能需求

### 4.1 数据安全

> 本节表述已于 2026-10-26 逐句代码核实，除导出格式外与实现一致。

- 患者健康数据加密：**客户端**本地库 SQLCipher（AES-256）+ 云端备份 AES-GCM 端到端密文（服务端仅存密文、不可解密）✅ **属实**（仅移动 App；PC Web 数据存明文 localStorage，敏感操作建议走 App）；服务端解析/同步中转数据当前为**明文存储** ✅ 属实（解析任务与业务 CRUD 明文；密文快照通道除外）；字段级加密（AES-256-GCM DEK）为目标设计，尚未落地 ✅ 属实（客户端存在加密函数但无调用方；医生授权的 wrappedDek 再包裹除外）
- 本地存储优先，云同步可选 ✅（云同步为手动触发的端到端密文快照，详见 §4.2.7）
- **"用完即删"** ➕：解析确认后默认删除云端 PDF 原件（幂等，独立删除端点 + `sourceDeleted` 状态）；注意"用完即删"限原件，解析后的结构化数据按业务需要保留
- **档案可追溯（V1.3 新增需求）**：删除原件时必须保留"已处理 PDF 清单、去重键、待核对状态、检查报告路径索引"，否则无法判断"这份报告是否处理过"（§2.1.6）。
- **检查类报告留存策略（V1.3 新增需求）**：检查报告默认保留路径/索引（可回溯、可复核年报）；图片附件仍 ❌。与"用完即删"的边界：删原件不删索引。
- **备份范围（V1.3 新增需求）**：产品化对应"导出目录约定"——备份为按日期目录的整体导出，范围覆盖全部记录模块（检验/检查/症状/用药/注射/变更史/就诊/营养/疫苗/心理），并保证"导出什么能恢复什么"；目录不放在公开云盘，分享前脱敏。
- 数据导出支持 — ⚠️ **实际为 JSON / CSV / Excel(xlsx) + 浏览器打印**（App：CSV 多表 + JSON 备份；Web：JSON/CSV/Excel + 打印视图）；**PDF 文件生成与 DOCX 未实现**（V1.0 所写"JSON/PDF/DOCX"不实，已修正；打印视图可由用户另存为 PDF）
- 隐私设计对齐《个人信息保护法》医疗数据原则（本地优先、最小上传、明确授权）；DPIA 与知情同意**模板已入库**（`docs/compliance/`，T7），**正式合规文本待法务定稿**（模板自带 ⛔ 标注）；非诊断/非治疗声明已在 5 个解读类页面常驻可见（T7）；生产安全复查清单见 `docs/security-checklist.md`
- ➕ 安全加固（PRD 未记载的已实现项）：CORS 白名单 + 生产禁用 Swagger；登录/上传/会话/授权码多层限流 + XFF 默认不信任；生产配置守卫；文件路径穿越/IDOR 防护；Skill 正则 ReDoS 防护；社区发布脱敏白名单；推送 payload 不含病历信息；DPoP-lite 设备持有证明（服务端核心已实现，请求级验签待启用）

#### 4.2.7 端间数据同步

> **V1.1 修订**：本节 V1.0 描述（实时同步/乐观锁/端间一致）为目标设计，当前实现为**手动密文快照**模式，已按实际更正。

**同步策略**（⚠️ 现状）：
- 本地权威：App 以本地 SQLCipher 库为唯一权威，核心功能无登录墙（`app_user_uuid` 本机标识）✅
- 云同步为**可选、手动触发**的端到端密文快照（口令派生密钥，上传/恢复/删除云端副本）⚠️
- 微信小程序依赖网络为主，打卡等轻量数据有本地暂存 ⚠️
- PC Web 与 App 数据**暂不互通**（Web 端为 localStorage 独立数据面，仅批量解析/Skill 社区走服务端）❌

**数据一致性**（⚠️ 现状 vs 目标）：
- 现状：快照级 `version` 大者胜；恢复为导入式，重复恢复会重复数据
- 目标：记录级时间戳乐观锁 + 同一设备优先 + 离线合并队列（**未实现**）
- 服务端已具备 HLC 混合逻辑钟字段与 deviceId 标记（为后续合并预留）➕
- 本机默认：`app_user_uuid`，**无登录墙**；核心功能不依赖账号 ✅
- 云能力（同步/恢复）可选：关联手机号 ✅（可解除关联）；微信 OAuth ⚠️ 仅为占位（本地标记），后端未接通
