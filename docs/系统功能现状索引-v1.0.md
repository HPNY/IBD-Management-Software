#### 2.3 M-14 发作预警的实际规则（`core/flare/flare_service.dart`）
- **红**：最近一条日记 `bloody_stool` 为 `obvious`/`trace`，或排便记录 `blood >= 1`；或 `pain_level >= 8`
- **黄**：近 3 天腹痛单调递增 / 腹泻单调递增 / 今日腹泻 ≥6 且比 3 天前多 2 次以上；无任何打卡也判黄（「数据不足」）
- **绿**：以上都不触发
- 黄/红时会顺带读 CRP 与钙卫蛋白末值写进理由

## 3. 8 处硬缺陷（「看起来做了、实际不可用」）

### 坑 #1 · i18n 是空壳，切 English 界面一处都不变
- `apps/mobile/lib/core/i18n/app_locale.dart` 里有 `String t(String key) => (isZh ? _zh : _en)[key] ?? key;`，也写了 20 个 key 的中英对照
- **全仓 `.t(` 调用数 = 0**；`AppLocale` 只出现在 `main.dart:63`（Provider）、`main.dart:96`（watch）、`settings_page.dart:752`（Consumer）
- 无 `.arb` 文件，无 ARB 生成链
- 用户可见后果：设置页切到 English → 除了开关本身高亮，**没有任何文字变化**

### 坑 #2 · 大字体模式反向生效（应用覆盖系统字号）
- `apps/mobile/lib/main.dart:104-109`：
  ```dart
  builder: (context, child) {
    final scale = context.watch<AccessibilityPrefs>().textScale;
    return MediaQuery(
      data: MediaQuery.of(context).copyWith(textScaler: TextScaler.linear(scale)),
      child: child ?? const SizedBox.shrink(),
    );
  },
  ```
- `TextScaler.linear(appScale)` 是**整个替换**而非相乘 → 系统设 2.0× 时被压回 1.0×（或开大字体时的 1.25×）
- `apps/mobile/lib/core/ui/accessibility.dart:16`：`double get textScale => _largeFont ? 1.25 : 1.0;`
- 全仓 `textScaler` 仅此 1 处；`apps/mobile/test` **没有任何字体缩放断言**
- ⚠️ `docs/session-worklist.md` 的 U12 行写的是「改为 `TextScaler.linear(system.scale(1.0) * appScale)` 相乘」——**文档与代码不符，属误记**

### 坑 #3 · 后端 31 个接口里 15 个 App 从未调用
`apps/mobile/lib/core/api/ibd_api_client.dart` 定义但**零调用方**的方法：
```
addAdverseEvent    completeInjection   createLab          createMedication
deleteObject       generateSchedule    listCurrentMedications   listDueReminders
listInjections     listLabs            listProtocols      medicationTimeline
stopMedication     switchMedication    updateMedication
```
- 实际被调用的只有 4 个页面：`features/lab/lab_entry_page.dart`（`deleteParseSource`）、`features/analysis/{my_doctors,geo_community,drug_review}_page.dart`
- 即：**App 的数据主体全在本机 SQLite**，后端只承担「解析上传 / 医生协作 / 同城 / 药物评价聚合 / 推送 / 密文同步」六件事
- 这不是 bug，但**PRD 里描述的「多端一致」在实现上是「多端各自独立」**，改进项若涉及多端必须正视这一点

### 坑 #4 · M-06 用药不良反应只有表和 API，没有 UI
- `repositories.dart:157 Future<String> addAdverseEvent(...)`、`:177 Future<List<Map<String,dynamic>>> adverseEvents(String medicationId)` 都实现了
- `backup_service.dart:79` 还会备份 `adverse_events` 表
- 但 `features/medication/medication_page.dart` 与 `medication_edit_page.dart` **零「不良反应 / 副作用」入口**
- `addAdverseEvent` 无任何调用方 → 表永远为空

### 坑 #5 · M-24 就诊指南硬编码 6 城市，但城市列表给 10 个
- `apps/mobile/lib/core/geo/geo_profile.dart` 的 `kCityGuide` 只有 6 条：北京 / 上海 / 广州 / 杭州 / 成都 / 武汉（如「复旦大学附属中山医院 消化内科」「四川大学华西医院 消化内科 手术型」）
- `kCities` 却是 10 个（多出 深圳 / 南京 / 西安 / 其他）
- `guidesForCity(city)` 精确匹配 → **深圳/南京/西安 用户永远看到「暂无该城市指南，可换城市查看」**（`geo_community_page.dart:231`）

### 坑 #6 · 疾病活动度只有三灯，没有任何标准评分
- `apps/mobile/lib/core/activity/activity_service.dart` 全 81 行；`inflammationLight(flag)` 只看 `flag == 'high' → 红`，`inflammationStateText` 给「偏高/正常/未测」
- `extractLimberg` / `extractSesCd` 用正则从自由文本抠分级
- **CDAI / HBI(Harvey-Bradshaw) / partial Mayo / SCCAI 全仓 0 命中**
- 后果：M-18 名为「疾病活动度仪表盘」，实际只能显示检验项的箭头，**无法回答「我现在活动度几分」**

### 坑 #7 · Web 端与 App 数据完全隔离，检验数据在 Web 侧没有产生路径
`apps/web` 用 `localStorage` 存储，共 4 个键，写入/读取方实测如下：

| 键 | 写入方 | 读取方 |
|---|---|---|
| `ibd_web_labs` | **仅** `apps/web/src/pages/DataExport.tsx:128`（`importJson`，需用户手动导入 JSON 文件） | `Trends.tsx:27`、`DataExport.tsx:13` |
| `ibd_web_clinical` | `apps/web/src/pages/ClinicalEdit.tsx:45`（手动录入检查/手术） | `DataExport.tsx:14` |
| `ibd_web_uid` | `ParseBatch.tsx:47` | `ParseBatch.tsx:44` |
| `ibd_app_user_uuid` | **App 侧写了**（`apps/mobile/lib/core/identity/local_identity.dart:6`），但那是**设备本地存储**，浏览器读不到 | `SkillCommunity.tsx:46`（永远拿 `undefined`） |

- 结论：**「趋势分析」页在真机上必然为空**——`ibd_web_labs` 只有「用户自己从别处导出 JSON 再导入」这一条产生路径，App 无法把检验数据交给它
- `ClinicalEdit` / `DataExport` 本身是可用的（有手动录入 + 导入），但数据只活在这个浏览器的 localStorage 里
- `SkillCommunity.tsx:46` 传的 `appUserId` 恒为 `undefined`，即社区发帖无法关联到 App 身份

### 坑 #8 · 「云同步」是手动密文快照，不是同步
- `settings_page.dart:324-325`：`SyncApi(ApiConfig.dev()).syncSession(...)` + `putCipher(...)`
- `settings_page.dart:391-392`：恢复走 `listCipher`
- `apps/mobile/lib/core/backup/backup_service.dart:389 Future<int> restoreFromCloud(...)`
- `settings_page.dart:413` 明写「恢复会按记录去重追加，不会清空现有数据」
- 无自动增量、无冲突合并、无后台同步 → 命名会让用户误以为是实时多端同步

## 6. 数据层（14 张本地表）

`apps/mobile/lib/core/db/local_db.dart`，`version: 10`（`:78`），`_onCreate` `:172` / `_onUpgrade` `:261`：

```

injections      symptom_diaries   parse_jobs       bathroom_records
```

- **`parse_jobs` 是死表**：全仓只有 `local_db.dart:248` 的 `CREATE TABLE` 一处出现，**没有任何 repository、没有读写代码**（历史遗留，可考虑在下次迁移中移除或补上用途）
- `adverse_events` 有 repository 有备份，但**无 UI 入口**（坑 #4）
- `food_logs` 正常：`FoodRepository`（`repositories.dart:615`）+ `food_stool_page.dart:97 _add`

## 10. 建议改进项的书写格式

为了让改进项能直接映射进任务清单，希望每条至少带：

1. **模块号**（M-01…M-26）或**页面名**（如「打卡页」「设置页 · 密文备份区」）
2. **优先级**：P0 / P1 / P2（你用自己的口径即可，我映射到项目 C1–C4）
3. **期望行为**：现在是什么、希望变成什么（一句话即可）
4. **是否影响数据**：涉及表结构变更的，需要单独排数据迁移

如果改进项正好落在 §3 的 8 个坑上，可以直接引用坑号（如「坑 #1」），省去描述。
