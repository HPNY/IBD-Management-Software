# IBD病程管理程序 — 产品需求文档（PRD）

> 基于克罗恩病患者真实病程管理经验设计

---

## 一、产品概述

### 1.1 产品名称
**IBDers** — IBD患者病程自我管理平台

### 1.2 产品定位
面向炎症性肠病（IBD，含克罗恩病和溃疡性结肠炎）患者的**病程记录与自我管理工具**，帮助患者系统化管理检验数据、用药记录、检查影像、注射排期等全病程信息，辅助医患沟通和治疗决策。

### 1.3 目标用户
- **核心用户**：确诊IBD的患者（克罗恩病、溃疡性结肠炎）
- **扩展用户**：患者家属/照护者、消化内科医生（查看患者自管数据）

### 1.4 产品背景
IBD是慢性病，患者需要终身管理。以一位典型克罗恩病患者的经历为例：

```
确诊 → 药物治疗 → 应答不佳换药 → 手术 → 术后恢复 → 多次方案调整
     → 生物制剂注射 → 定期检验复查 → 影像/内镜随访
```

这个过程中，患者面临的信息管理痛点：
- **检验报告分散**：纸质报告、PDF、医院APP，数据碎片化
- **指标趋势难追踪**：CRP、钙卫蛋白、血沉等关键指标跨年度对比困难
- **用药历史复杂**：多种药物、剂量调整、停药原因需要完整记录
- **注射排期易遗漏**：生物制剂有严格的注射时间窗口
- **医患信息不对称**：患者难以向医生清晰呈现完整病史

## 二、核心功能

### 2.1 检验数据管理

#### 2.1.1 PDF报告智能解析

**功能描述**：支持上传医院检验/检查报告PDF，通过**AI智能识别**自动提取关键数据，并对已解析过的医院格式生成解析模板（Skill），实现"越用越准"。

##### 解析架构：双引擎模式

```
用户上传PDF
    │
    ▼
┌──────────────────┐
│   Skill模板匹配   │ ←── 已学习的医院格式模板库
│  （优先命中）      │
└────────┬─────────┘
         │未命中
         ▼
┌──────────────────┐
│   AI智能解析引擎   │ ←── 大模型 + Vision能力
│  （通用兜底）      │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│   结构化数据输出   │
│  + 用户确认/修正   │
└────────┬─────────┘
         │首次解析成功
         ▼
┌──────────────────┐
│  自动生成/更新Skill │ ←── 沉淀为该医院的解析模板
└──────────────────┘
```

##### 引擎一：Skill模板解析（快速通道）

**核心理念**：每家医院的报告格式是固定的，首次解析后生成Skill模板，后续同类报告直接套用模板提取，速度更快、准确率更高。

**Skill模板内容**：
```yaml
hospital: 某三甲医院A
report_type: 血常规（五分类）
version: 1.2
last_updated: YYYY-MM-DD

# 日期提取规则
date_extraction:
  primary: '(\d{8})G\d+'  # 样本号格式
  fallback: '采集日期:\s*(\d{4})/(\d{1,2})/(\d{1,2})'

# 项目提取规则（支持同行和跨行）
items:
  - name: 白细胞计数
    alias: WBC
    pattern: '白细胞计数\s+([\d.]+)'
    multiline: true  # 数值可能在下一行
    unit: '10^9/L'
    ref_range: [3.5, 9.5]
    check_fn: 'v < 3.5 or v > 9.5'

  - name: 血红蛋白
    alias: Hb
    pattern: '血红蛋白\s+([\d.]+)'
    unit: 'g/L'
    ref_range: [130, 175]
    check_fn: 'v < 130'

  # ... 更多项目

# 特殊处理规则
special_rules:
  - filter: 'patient_id_mismatch'  # 病案号误匹配过滤
    description: '病案号[病案号]可能被匹配为检验值'
    condition: 'value == [病案号]'
    action: 'discard'

  - filter: 'crp_multiline'  # CRP跨行处理
    description: '超敏C-反应蛋白标签和数值常分两行'
    pattern: '超敏C-反应蛋白'
    next_line_pattern: '^([\d.]+)'
    value_filter: '< 100'
```

**Skill模板管理**：
- 每家医院可生成多个Skill（按报告类型区分：血常规、肝功能、超声等）
- 同一医院同一报告类型的Skill支持**版本迭代**（用户修正后自动更新）
- Skill可在用户间**共享**（社区贡献），降低新用户的学习成本
- 支持导出/导入Skill模板

##### 引擎二：AI智能解析（通用兜底）

**适用场景**：
- 首次遇到的医院报告格式（无Skill模板）
- 图片型/扫描型PDF（OCR + 理解）
- 格式特殊的报告（如手写、非标准排版）

**AI解析流程**：

| 步骤 | 处理方式 | 说明 |
|------|---------|------|
| 1. PDF读取 | pymupdf | 文字型PDF直接提取文本；图片型PDF转高分辨率图像 |
| 2. 文本/图像理解 | 大语言模型 | 输入原始文本或图像，AI理解报告结构和内容 |
| 3. 结构化提取 | AI + 规则校验 | 输出标准化的JSON结构，包含所有检验项目、数值、单位、参考范围 |
| 4. 异常标注 | 规则引擎 | 根据参考范围自动标注 ↑/↓ |
| 5. 结果确认 | 用户交互 | 用户确认/修正提取结果 |

**AI Prompt设计示例**：
```
你是一名医学检验报告解析助手。请从以下检验报告文本中提取所有检验项目，
返回JSON格式，包含以下字段：
- name: 项目中文名称
- value: 数值结果（浮点数）
- unit: 单位
- ref_min: 参考范围下限（如有）
- ref_max: 参考范围上限（如有）
- flag: 异常标记（↑/↓/null）

特别注意：
1. 有些报告的项目名和数值分两行显示，请识别关联
2. 过滤掉病案号、样本号等非检验数值
3. 区分">1800"这样的上限值和具体数值

报告文本：
{report_text}
```

**Vision能力（图片型PDF）**：
- 对扫描件/拍照件PDF，渲染为高分辨率图像（3x缩放）
- 使用多模态大模型直接识别图像中的检验数据
- 支持手写批注的识别（如医生手写的诊断意见）

##### 双引擎协作机制

| 场景 | 处理路径 | 速度 | 准确率 |
|------|---------|------|--------|
| 已有Skill模板 | 模板解析 → 输出 | 极快（<1s） | 极高（99%+） |
| 首次该医院报告 | AI解析 → 用户确认 → 生成Skill | 较慢（3-5s） | 高（95%+） |
| 图片型PDF | Vision AI → 用户确认 | 较慢（5-10s） | 中高（90%+） |
| Skill解析失败 | 降级到AI解析 → 更新Skill | 中等 | 高 |

**Skill自动生成/更新逻辑**：
1. 用户上传PDF，无匹配Skill → AI解析 → 用户确认 → **自动生成新Skill**
2. 用户上传PDF，Skill解析成功但遗漏字段 → AI补全 → 用户确认 → **自动更新Skill版本**
3. 用户手动修正AI/Skill解析结果 → **将修正反馈回Skill**，提升下次准确率
4. 用户在不同医院检查 → 按医院分别维护独立的Skill库

**输出格式**：
- 中文项目名称（非英文缩写）
- 按时间排列的结构化数据表
- 异常值用 ↑↓ 标注
- 数据来源标记（Skill解析/AI解析/手动录入）

#### 2.1.2 手动录入
**功能描述**：支持手动录入检验数据，适配以下场景：
- 报告为纸质版或图片，无法自动解析
- 需要补录历史数据
- 患者在不同医院检查，报告格式不统一

**录入界面设计**：
- 按检验类别分组（血常规、肝功能、炎症指标等）
- 每个指标显示参考范围作为输入参考
- 输入异常值时自动提示 ↑ 或 ↓

#### 2.1.3 指标趋势分析
**功能描述**：以图表形式展示关键指标的时间趋势。

**IBD核心指标面板**：

| 指标 | 参考范围 | 临床意义 |
|------|---------|---------|
| 超敏C反应蛋白 | <5.0 mg/L | 全身炎症活动度 |
| 血沉 | <15 mm/h | 炎症活动度（滞后指标） |
| 粪便钙卫蛋白 | <200 μg/g | **肠道炎症金标准**，最敏感 |
| 淋巴细胞 | 1.1-3.2×10⁹/L | 免疫状态，用药感染风险 |
| 白蛋白 | 40-55 g/L | 营养状态 |
| 血红蛋白 | 130-175 g/L | 贫血评估 |
| 尿酸 | 208-428 μmol/L | 药物副作用监测 |

**趋势分析功能**：
- 支持自定义时间范围（3个月/6个月/1年/全部）
- 多指标叠加对比（如CRP+钙卫蛋白）
- 标注用药变更节点（换药、增减剂量）在图表上
- 关键阈值线（如钙卫蛋白200缓解线）
- 生成趋势摘要文字（如"CRP从10.5持续降至2.2，改善明显"）

#### 2.1.4 检查/影像报告管理
**功能描述**：管理非检验类的检查报告（CT、MRI、超声、内镜、病理等）。

**支持的检查类型**：
- 影像学：CT、MRI、X光、超声
- 内镜：胃肠镜报告
- 病理：活检病理报告
- 特殊检查：胶囊内镜、小肠造影等

**结构化存储**：
- 检查日期、检查类型、检查部位
- 关键发现（文字摘要）
- 与历史检查的对比（如"较前好转"）
- 评分系统记录（如SES-CD、Limberg分级、IBUS-SAS评分）

### 2.2 用药管理

#### 2.2.1 当前用药方案
**功能描述**：记录当前在用的所有药物及其详细信息。

**药物信息字段**：

| 字段 | 说明 | 示例 |
|------|------|------|
| 药物名称 | 通用名+商品名 | 乌帕替尼（Rinvoq） |
| 药物类别 | 机制分类 | JAK抑制剂 |
| 适应症 | 治疗目标 | 克罗恩病维持治疗 |
| 剂量 | 单次剂量 | 15mg |
| 频次 | 给药频率 | 隔天一次 |
| 给药方式 | 口服/皮下/静脉 | 口服 |
| 起始日期 | 开始使用日期 | [起始日期] |
| 状态 | 在用/暂停/停用 | 在用 |

#### 2.2.2 用药历史时间线
**功能描述**：完整记录所有曾用药物、剂量调整、停药原因。

**记录维度**：
- 药物切换链：修美乐→安健宁→乌帕替尼3颗→停药→乌帕替尼1颗→停药→乌司奴单抗→乌帕替尼隔天→+利生奇珠单抗
- 每次调整的原因（应答不佳/副作用/医保/医生建议）
- 副作用记录（带状疱疹、反复感染等）及严重程度
- 停药时长及恢复过程

**时间线可视化**：
```
2023     2024        2025                    2026
├─修美乐─┤─安健宁────┤─乌帕替尼3颗→停→1颗→停→┤─乌帕替尼隔天──→
                                                  └─+利生奇珠─→
                              ↑带状疱疹    ↑感冒不愈
```

#### 2.2.3 生物制剂注射管理
**功能描述**：专为使用生物制剂的患者设计的注射排期管理。

**支持的注射药物**（可扩展）：
- 利生奇珠单抗（Skyrizi/喜开悦）— IL-23抑制剂
- 英夫利昔单抗（类克）— TNF-α抑制剂
- 阿达木单抗（修美乐/安健宁）— TNF-α抑制剂
- 乌司奴单抗（喜达诺）— IL-12/23抑制剂
- 维得利珠单抗（安吉优）— 整合素抑制剂

**注射排期功能**：
- 根据药物方案自动生成注射日历
- 区分诱导期和维持期的不同频率
- 注射前X天提醒（可配置，默认3天）
- 记录每次实际注射日期（可能与计划有偏差）
- 延迟注射后自动调整后续排期

**利生奇珠单抗示例排期**：
```
诱导期（静脉输注 600mg）：
  Week 0  → [日期] ✅
  Week 4  → [日期] ✅
  Week 8  → [日期] ✅

维持期（皮下注射，每8周一次）：
  Week 12 → [日期] ⏳ 首次皮下
  Week 20 → [日期]
  Week 28 → [日期]
```

### 2.3 手术记录管理

#### 2.3.1 手术信息结构化存储
**功能描述**：记录手术的完整信息，支持文字+影像附件。

**字段设计**：

| 字段 | 说明 |
|------|------|
| 手术日期 | 精确到日 |
| 手术类型 | 切除/成形/造口等 |
| 手术部位 | 小肠/结肠/直肠等 |
| 术中所见 | 病变描述（文字+示意图） |
| 手术方式 | 具体操作描述 |
| 切除长度 | 切除肠管的长度 |
| 吻合方式 | KONO-S/端端/侧侧等 |
| 术中评分 | 如克罗恩病手术评分 |
| 术后评分 | 术后评估 |
| 主刀医师 | 姓名 |
| 附件 | 手术记录照片/扫描件 |

#### 2.3.2 手术示意图管理
**功能描述**：支持上传术中示意图，标注病变位置和手术操作。

- 支持上传手术记录照片（如IBD术中情况示意图）
- 支持在肠道解剖图上标注病变位置
- 记录肠管总长度、剩余长度

### 2.4 病程时间线

#### 2.4.1 全病程时间线
**功能描述**：将所有病程事件整合为一条完整的时间线。

**时间线事件类型**：
- 🔴 疾病事件（确诊、复发、并发症）
- 🟡 检查事件（检验、影像、内镜、病理）
- 💊 用药事件（开始/调整/停用药物）
- 🏥 手术事件
- 💉 注射事件
- ⚠️ 不良反应事件

**交互设计**：
- 支持按年/月缩放
- 支持按事件类型筛选
- 点击事件查看详情
- 支持导出为PDF（用于就诊时给医生看）

#### 2.4.2 就诊摘要生成
**功能描述**：自动生成一份结构化的就诊摘要，方便患者在门诊时快速向医生汇报病情。

**摘要内容**：
```
【患者信息】[患者姓名]，男，[年龄]岁，确诊克罗恩病3年余

【当前用药】
1. 乌帕替尼 隔天1颗（JAK抑制剂）
2. 利生奇珠单抗 维持期，每8周皮下注射

【最近检验（[日期3]）】
[CRP值] | [ESR值] | [钙卫蛋白值]
[淋巴细胞值] | [尿酸值]

【近期影像】
腹部超声([日期]): Limberg [分级]，[所见]

【关注事项】
1. 钙卫蛋白仍偏高，需持续监测
2. 淋巴细胞持续偏低，感染风险
3. 尿酸长期偏高
```

### 2.5 提醒与随访

#### 2.5.1 注射提醒
- 注射前3天、1天推送提醒
- 注射当天提醒携带相关证件/医保卡
- 皮下注射药物提醒观看OBI操作视频

#### 2.5.2 复查提醒
- 根据用药方案自动建议复查时间
- 提醒需要复查的项目列表
- 支持自定义提醒

#### 2.5.3 用药提醒
- 口服药物每日/隔日提醒
- 记录服药依从性

### 2.6 数据可视化

#### 2.6.1 疾病活动度仪表盘
**功能描述**：综合多个指标，展示当前疾病活动度。

**仪表盘元素**：
- 炎症三联指标状态灯（CRP/ESR/钙卫蛋白）
- Limberg分级趋势（超声）
- SES-CD评分趋势（内镜）
- 当前用药方案卡片
- 下次注射/复查倒计时

#### 2.6.2 年度健康报告
**功能描述**：每年自动生成一份健康总结报告。

> **实现状态（2026-09）**：当前为**临时手动实现**——用户在分析页按年触发生成并分享，**尚未**到期自动汇总。完整能力（自动生成、同比、检查/手术汇总等）待后续按原版设计补全，见 worklist G3。

**报告内容**：
- 年度关键指标变化趋势
- 用药调整记录
- 检查/手术记录汇总
- 与上一年度对比

### 2.7 症状与生活质量管理

> 本模块借鉴MyCrohnsAndColitisTeam、MyGut等竞品的设计理念，弥补当前PRD在患者日常自我管理维度的缺失。

#### 2.7.1 每日症状日记
**功能描述**：每日花1-2分钟记录当日症状状态，形成纵向症状数据。

**记录项目**：

| 类别 | 记录项 | 形式 |
|------|--------|------|
| 腹痛 | 程度（0-10分）| 滑块 |
| 腹泻 | 次数 + 性质（ Bristol粪便量表1-7型）| 数字+选择 |
| 便血 | 无/少量/明显 | 单选 |
| 腹胀 | 程度（0-10分）| 滑块 |
| 疲劳 | 程度（0-10分）| 滑块 |
| 恶心 | 有/无 | 开关 |
| 口腔溃疡 | 有/无 | 开关 |
| 关节痛 | 有/无 + 部位 | 开关+选择 |
| 自定义 | 患者可添加个人关注项 | 文字 |

**交互设计**：
- 首页常驻"今日打卡"入口，1分钟内完成
- 支持快捷模板（"和昨天一样" / "比昨天好/差"）
- 日历视图：颜色深浅代表症状严重程度
- 未记录日期灰色提示，鼓励连续记录

#### 2.7.2 排便记录
**功能描述**：IBD患者最核心的日常指标——排便情况的精细化追踪。

**记录项**：
- 时间
- 次数（当日累计）
- 性质（Bristol粪便量表 1-7型）
  - 1型：坚果状硬球
  - 4型：光滑香肠状（理想）
  - 7型：水样便
- 紧迫感（有/无）
- 便血（无/擦拭有/明显）
- 黏液（有/无）

**数据价值**：
- 与钙卫蛋白、CRP等指标关联分析
- 发现食物-排便模式的关联
- 就诊时提供客观数据，而非主观描述

#### 2.7.3 发作预警（Flare Checker）
**功能描述**：基于症状数据和历史模式，评估当前是否有发作风险。

**三级预警机制**：

| 级别 | 触发条件 | 建议 |
|------|---------|------|
| 🟢 正常 | 症状评分稳定，排便正常 | 继续观察 |
| 🟡 关注 | 症状连续3天加重，或排便次数突增 | 建议近期复查CRP+钙卫蛋白 |
| 🔴 警告 | 便血、发热>38°C、剧烈腹痛 | 建议立即就医 |

**AI辅助判断**：
- 结合每日症状数据 + 最近检验指标 + 用药状态综合评估
- 参考历史发作前的症状模式（如"上次发作前7天腹泻加重"）
- 预警时自动生成症状摘要，可直接发给医生

#### 2.7.4 生活质量评估
**功能描述**：定期评估疾病对生活质量的整体影响。

**评估量表**：
- **SF-36**（通用生活质量量表）— 每月一次
- **IBDQ**（IBD专用生活质量量表）— 每季度一次
- **PHQ-9**（心理健康筛查）— 每月一次

**应用场景**：
- 纵向追踪生活质量变化趋势
- 评估治疗方案对生活质量的整体改善
- 识别心理健康风险（IBD患者抑郁/焦虑风险高于普通人群）

#### 2.7.5 睡眠与压力追踪
**功能描述**：睡眠质量和心理压力是IBD发作的重要诱因。

**记录项**：
- 睡眠时长
- 睡眠质量（1-5分）
- 入睡困难（有/无）
- 夜间醒来（次数）
- 压力水平（1-10分）
- 压力来源（工作/家庭/疾病/其他，可选填）

**数据关联**：
- 分析"压力大→几天后症状加重"的延迟关联
- 识别睡眠质量与排便异常的模式
- 为患者提供可量化的自我管理建议（如"连续3天睡眠<6小时后，腹泻概率增加40%"）

#### 2.7.6 药物治疗评价
**功能描述**：患者对使用过的药物进行主观评价，帮助其他病友参考。

**评价维度**：
- 整体疗效（1-5星）
- 副作用严重程度（无/轻/中/重）
- 副作用类型（多选：感染、皮疹、胃肠反应、头痛等）
- 是否仍在使用
- 文字评价（可选）

**社区共享**：
- 按药物聚合评分（如"乌帕替尼：4.2分，328条评价"）
- 按IBD类型筛选（克罗恩 vs 溃疡性结肠炎）
- 不替代医生建议，仅供参考

#### 2.7.7 同城病友与就诊指南
**功能描述**：帮助患者找到同城病友和优质的IBD专科资源。

**同城病友**：
- 基于地理位置匹配同城IBD患者
- 匿名显示（昵称+城市，不显示真实姓名）
- 可组建本地群组（如"杭州IBD病友群"）

**就诊指南**：
- 各城市IBD专科医院/科室推荐
- 医生擅长方向（如手术型/药物型/疑难型）
- 就诊流程攻略（挂号、检查、住院经验）
- 医保政策经验分享

├── phase: 阶段（诱导期/维持期）
├── dose: 剂量
├── route: 给药方式（静脉/皮下）

## 四、非功能需求

### 4.1 数据安全
- 患者健康数据加密存储（AES-256）
- 本地存储优先，云同步可选
- 数据导出支持（JSON/PDF/DOCX格式）
- 符合《个人信息保护法》医疗数据相关规定

### 4.2 客户端类型规划

#### 4.2.1 整体架构

```
┌─────────────────────────────────────────────────────┐
│                    后端服务层                         │
│   用户管理 | 数据存储 | AI解析引擎 | 推送服务         │
└──────────┬──────────┬──────────┬──────────┬──────────┘
           │          │          │          │
     ┌─────┴───┐ ┌────┴────┐ ┌──┴──┐ ┌────┴────┐
     │ 移动App │ │ 微信小程序│ │ PC  │ │ 医生端  │
     │ (核心)  │ │ (轻量)  │ │ Web │ │ (Web)  │
     └─────────┘ └─────────┘ └─────┘ └─────────┘
```

#### 4.2.2 移动App（Android + iOS）— 主力客户端

**定位**：患者日常使用的核心平台，承载高频交互场景

**适合放在App上的功能**：

| 功能模块 | 原因 |
|---------|------|
| 每日症状日记 | 高频操作，需随时记录 |
| 排便记录 | 即时性需求，随手上报 |
| 注射/用药提醒 | 需要系统级推送通知 |
| 发作预警 | 结合症状数据实时评估 |
| PDF拍照上传 | 利用手机摄像头 |
| 注射排期日历 | 日常查看 |
| 睡眠/压力记录 | 每日打卡 |

**技术方案**：
- 跨平台框架：Flutter 或 React Native（一套代码双端运行）
- 本地数据库：SQLite/Hive（离线数据缓存）
- 推送服务：APNs（iOS）+ FCM/厂商推送（Android）
- 相机/相册：PDF拍照上传、手术记录扫描

**离线能力**：
- 症状日记、排便记录支持离线填写，联网后自动同步
- 已下载的检验报告可离线查看
- 注射/用药提醒不依赖网络

#### 4.2.3 微信小程序 — 轻量入口

**定位**：降低获客门槛，提供轻量级服务，适合不习惯下载独立App的用户

**适合放在小程序上的功能**：

| 功能模块 | 原因 |
|---------|------|
| 检验报告查看 | 便捷查看已同步的数据 |
| 注射/复查提醒 | 微信消息推送，无需额外App |
| 就诊摘要查看/分享 | 微信内直接转发给医生 |
| 症状日记（简化版） | 1分钟快速打卡 |
| 社区互动 | 微信社交场景天然适配 |
| Skill社区浏览 | 浏览/下载其他用户分享的解析模板 |

**不适合放在小程序上的功能**：
- PDF上传解析（小程序文件操作受限）
- 复杂的趋势图表（屏幕和交互受限）
- 离线功能（小程序无本地数据库）
- 推送提醒的可靠性不如原生App

**技术方案**：
- 微信原生小程序 或 Taro/uni-app 跨端框架
- 与App共用后端API
- 微信登录为**可选关联**（非登录墙）；无登录也能用核心浏览/打卡

**获客策略**：
- 小程序作为**试用入口**，体验核心功能后引导下载完整App
- 医院场景扫码关注（如IBD门诊候诊区二维码）
- 病友群内分享小程序卡片，零安装传播

#### 4.2.4 PC Web端 — 深度分析平台

**定位**：面向需要深度数据管理和分析的场景，大屏幕更适合复杂操作

**适合放在Web上的功能**：

| 功能模块 | 原因 |
|---------|------|
| 多年检验数据对比表 | 大表格在PC上更易浏览 |
| 多指标趋势图表 | 大屏幕展示更清晰 |
| PDF批量上传解析 | PC端文件操作更便捷 |
| 手术记录管理 | 复杂表单填写更舒适 |
| 年度健康报告 | 完整报告在PC上阅读/导出更方便 |
| 就诊摘要编辑/导出 | PC端编辑和PDF导出更顺畅 |
| 数据导出（JSON/Excel） | PC端操作文件更自然 |
| Skill模板管理 | 创建/编辑解析模板需要详细表单 |

**技术方案**：
- 前端：React 或 Vue.js + ECharts/D3.js（数据可视化）
- 响应式设计：适配笔记本和台式机显示器
- 打印优化：就诊摘要、年度报告支持浏览器打印

**使用场景**：
- 诊前准备：在PC上整理病程数据，生成就诊摘要打印带去医院
- 深度分析：对比多年的检验趋势、用药节点与指标变化
- 数据管理：批量导入历史PDF报告、手动补录数据

#### 4.2.5 医生端Web（V2.0）— 医患协作

**定位**：医生查看患者自管数据、标注建议的专用界面

**功能**：
- 患者授权后查看其病程数据
- 查看患者症状日记和发作预警
- 标注医学建议（如"建议复查钙卫蛋白"）
- 远程问诊时同步病程摘要

**技术方案**：
- 独立Web应用，与患者端数据隔离
- 医生身份认证（执业医师证验证）
- 患者主动授权机制（扫码/邀请码）

#### 4.2.7 端间数据同步

**同步策略**：
- 核心数据（症状、排便、检验）通过云端实时同步
- 移动App支持离线操作，联网后自动合并
- 微信小程序依赖网络，不缓存本地数据
- PC Web与App数据实时一致（同一后端API）

**数据一致性**：
- 基于时间戳的乐观锁冲突解决
- 同一设备优先（如手机填写的症状日记不会被PC端覆盖）
- 本机默认：`app_user_uuid`，**无登录墙**；核心功能不依赖账号
- 云能力（同步/恢复）可选：关联手机号或微信 OAuth（非强制登录）；关联后可注销，不影响本机数据

#### 4.2.8 开发优先级

| 阶段 | 客户端 | 时间 | 说明 |
|------|--------|------|------|
| P0 | 移动App（Flutter跨端） | 与MVP同步 | 核心产品，承载全部高频功能 |
| P1 | 微信小程序 | MVP 壳 + 功能可后置 | 获客入口；MVP 优先 App，小程序脚手架/四页可与 MVP 并行，登录/订阅消息等依赖外部凭据可晚 |
| P1 | PC Web端 | V1.0阶段 | 深度分析和数据管理 |
| P2 | 医生端Web | V2.0阶段 | 医患协作 |

### 4.3 性能要求
- PDF解析响应时间 < 5秒
- 趋势图表渲染 < 1秒
- 数据同步延迟 < 3秒

### 4.4 可用性
- 大字体模式（适配老年患者）
- 简洁模式（只显示核心指标）
- 支持中英文切换

## 五、扩展功能（V2.0）

### 5.1 医患协作
- 患者授权后，医生可查看患者自管数据
- 医生端可标注建议（如"建议下次复查钙卫蛋白"）
- 远程问诊时自动同步病程摘要

### 5.2 AI辅助分析
- 基于历史数据预测疾病活动趋势
- 异常指标预警（如"钙卫蛋白连续两次升高，建议就医"）
- 用药效果评估（如"联合用药后CRP下降62%，方案有效"）

### 5.3 解析Skill社区

**核心理念**：每位患者解析过的医院报告格式可以贡献给社区，让同医院的其他患者直接使用，无需从零学习。

**功能设计**：
- 用户A首次解析"某三甲医院A血常规"并确认 → 自动生成Skill
- 用户A选择**发布到社区** → 其他某三甲医院A患者可直接使用该Skill
- 社区Skill有**评分和评价**机制，优选高准确率模板
- 医院格式更新时（如系统升级），社区成员可协作更新Skill版本

**社区价值**：
| 参与方 | 获益 |
|--------|------|
| 首次使用者 | 无需等待AI解析，直接使用社区Skill，秒级出结果 |
| Skill贡献者 | 贡献积分/荣誉，优先使用社区高质量Skill |
| 社区整体 | 覆盖医院越多，新用户上手越快，形成网络效应 |

**医院格式覆盖率目标**：

- 长期：全国所有三甲医院 + 主要二甲医院

## 六、竞品分析

| 产品 | 优势 | 不足 |
|------|------|------|
| 丁香医生 | 用户基数大，内容丰富 | 无IBD专属病程管理功能 |
| 微医 | 在线问诊便捷 | 数据管理碎片化 |
| MyCrohnsAndColitisTeam | IBD社区活跃 | 英文，无中国医院数据对接 |
| 各医院APP | 可查本院报告 | 数据孤岛，无跨院整合 |

**本产品差异化优势**：
1. **IBD专属**：针对克罗恩病和溃疡性结肠炎的全病程管理设计
2. **报告解析**：AI+Skill双引擎自动解析医院PDF检验报告，越用越准
3. **注射管理**：生物制剂专属的注射排期和提醒系统
4. **全病程视角**：检验+影像+内镜+用药+手术+症状的统一时间线
5. **就诊辅助**：一键生成结构化就诊摘要
6. **症状日记**：每日症状+排便+睡眠+压力的完整追踪，关联检验指标
7. **发作预警**：基于症状模式和检验数据的AI预警系统

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 医院PDF格式不统一 | 解析成功率低 | 优先适配Top10三甲医院格式，开放自定义模板 |
| 患者手动录入意愿低 | 数据不完整 | 以PDF自动解析为主，降低录入门槛 |
| 医疗数据合规风险 | 法律风险 | 数据本地存储优先，云同步需明确授权 |
| 专业医学术语门槛 | 用户理解困难 | 提供通俗化解释（如"钙卫蛋白=肠道炎症温度计"） |
| 竞品跟进 | 市场竞争 | 深耕IBD垂直领域，建立数据壁垒 |
